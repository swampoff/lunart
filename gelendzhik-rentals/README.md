# Апартаменты в частном доме, Геленджик

Сайт частного дома, в котором сдаются апартаменты: гость смотрит дом, выбирает подходящую
квартиру, бронирует даты и вносит предоплату онлайн.

Приложение самостоятельное и не связано с остальным содержимым репозитория.

## Модель предметной области

Один **дом** — общий адрес, двор, бассейн, парковка, правила и контакты.
Внутри несколько **апартаментов** — у каждых своя вместимость, площадь, этаж, цена и календарь
занятости. Бронируются именно апартаменты, а не дом целиком.

Отсюда следуют решения, которые видны в интерфейсе:

- Занятые апартаменты не пропадают из списка, а показываются с пометкой «Занято на эти даты»:
  в доме их всего пять, и гостю важно видеть, что ещё есть.
- На странице апартаментов отдельным блоком показана общая территория дома и его правила —
  они одинаковы для всех квартир и не дублируются в описаниях.
- Если выбранные апартаменты заняты, внизу страницы предлагаются свободные соседние.

## Что умеет

**Гость**

- Смотрит дом: фотографии, описание, общая территория, что рядом, правила.
- Ищет по датам и числу гостей — сразу видит, какие апартаменты свободны и сколько стоят.
- Фильтрует по вместимости, числу комнат, цене и удобствам.
- Открывает карточку: галерея, описание, удобства, календарь занятости, расчёт стоимости.
- Бронирует и оплачивает предоплату картой; получает номер брони вида `ГЛД-A1B2C3`.
- Проверяет статус брони по номеру, повторяет оплату или отменяет бронь.

**Владелец**

- Правит апартаменты в массиве `APARTMENTS` (`server/seed.ts`) — при перезапуске каталог
  обновится, существующие брони не пострадают.
- Меняет данные дома в `server/house.ts`: адрес, описание, территория, правила, телефон.
- Закрывает даты вручную через таблицу `blocked_dates` — например, для броней по телефону.
- Подключает боевой эквайринг ЮKassa двумя переменными окружения.

## Как считается цена

Базовая цена апартаментов умножается на сезонный коэффициент **для каждой ночи отдельно**,
поэтому поездка на стыке сезонов считается честно:

| Сезон       | Месяцы               | Коэффициент |
| ----------- | -------------------- | ----------- |
| низкий      | ноябрь — март        | 0.65        |
| межсезонье  | апрель, май, октябрь | 0.85        |
| высокий     | июнь, сентябрь       | 1.15        |
| пиковый     | июль, август         | 1.45        |

Дальше применяется скидка за срок (от 7 ночей — 7%, от 28 ночей — 15%), прибавляется уборка.
Онлайн списывается 30% — остаток гость отдаёт при заселении. Логика собрана в
`server/pricing.ts`, менять сезоны и скидки нужно там.

## Как работает бронирование

1. `POST /api/bookings` в одной транзакции проверяет занятость и создаёт бронь со статусом
   `awaiting_payment`. Два одновременных запроса на одни даты не пройдут оба: второй получит
   `409 dates_taken`.
2. Даты держатся за гостем 30 минут (`HOLD_MINUTES` в `server/availability.ts`). Неоплаченные
   брони переходят в `expired`, и даты возвращаются в продажу.
3. Оплата подтверждается **только webhook-ом провайдера** — возврат гостя на сайт статус не
   меняет. После `payment.succeeded` бронь становится `paid`.

Заезд и выезд в один день конфликтом не считаются: интервалы пересекаются, только если начало
одного строго раньше конца другого.

## Запуск

```sh
npm install
npm run images   # генерирует SVG-заглушки для дома и апартаментов
npm run dev      # API на :3001, сайт на http://localhost:5173
```

Продакшен-сборка — один процесс, который отдаёт и API, и статику:

```sh
npm run build
NODE_ENV=production PORT=3000 npm start
```

Данные лежат в SQLite-файле `data/rentals.db`, апартаменты загружаются при старте сервера.

## Оплата

По умолчанию `PAYMENT_PROVIDER=mock`: вместо банка открывается страница `/pay/:id`, где оплату
можно подтвердить или отклонить вручную. Реальные деньги не списываются, ключи не нужны.

Боевой приём платежей включается переменными окружения (см. `.env.example`):

```sh
PAYMENT_PROVIDER=yookassa
YOOKASSA_SHOP_ID=<из личного кабинета>
YOOKASSA_SECRET_KEY=<из личного кабинета>
PUBLIC_URL=https://ваш-домен
```

После этого в личном кабинете ЮKassa нужно указать адрес для уведомлений:
`https://ваш-домен/api/payments/webhook` (события `payment.succeeded` и `payment.canceled`).

Что стоит сделать перед приёмом настоящих платежей:

- Ограничить `/api/payments/webhook` по IP-адресам ЮKassa — подписи у уведомлений нет.
- Проверить `vat_code` в чеке (`server/payments/yookassa.ts`) под свою систему налогообложения:
  сейчас стоит `1` — «без НДС».
- Настроить отправку письма с подтверждением: сейчас данные для заселения показываются на
  странице брони, но не отправляются на почту.

Другой провайдер подключается реализацией интерфейса `PaymentProvider`
(`server/payments/provider.ts`) — код бронирования при этом не меняется.

## Структура

```
server/           API на Express + SQLite
  house.ts        данные дома: адрес, территория, правила, контакты
  seed.ts         апартаменты дома
  pricing.ts      сезоны, скидки, расчёт стоимости
  availability.ts занятость дат и удержание броней
  routes/         дом и апартаменты, бронирование, платежи
  payments/       провайдеры оплаты (mock, ЮKassa)
shared/types.ts   общие типы сервера и клиента
src/              интерфейс на React + Vite + Tailwind
tests/            тесты цен и занятости (npm test)
scripts/          генератор изображений-заглушек
```

## Фотографии

В `public/images` лежат сгенерированные SVG-заглушки: `house-1…4` — общие виды дома,
`<slug>-1…4` — интерьеры апартаментов. Настоящие фотографии кладутся туда же под теми же
именами либо прописываются в `server/house.ts` и в поле `images` таблицы `apartments` —
код менять не нужно.
